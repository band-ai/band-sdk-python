# Portable schemas

`protocol.schema.json` uses JSON Schema draft 2020-12. Select a named `$defs`
entry with a local `$ref`; the top-level document is a definition registry, not
an implicit envelope. The `$id` is a stable identifier and need not be fetched.

The definitions cover normalized compiler input/output, session state, decisions,
views, portable full/redacted checkpoints, program ABI, exact invocation records,
journal frames and requirements. Unknown fields are rejected on closed protocol
objects. User payload/state maps remain open where their own schema permits it.

The Band binding adds `band_uuid`, `band_actor`, `band_session_config`,
`band_create_request`, `band_view_request`, `band_envelope` and
`band_http_identity`. These constrain existing typed-principal/UUID rules;
they do not replace shared decision or projection shapes. Unlike the shared
identity, Band requires the durable inbox capability. `band_wire_examples`
records positive and negative structural expectations which the checker
actually evaluates. See the [Band binding](../band-transport.md) for semantic
checks and byte bounds that schemas cannot establish. In particular,
`x-maxCanonicalBytes` and `x-maxUtf8Bytes` are documented constraints, not
standard validator keywords.

The current `protocol-v2.schema.json` and its descendant bundles add `carrier`
for `band-contract/carrier/1` maps and `carrier_identity` for the full resolved
binding-owned session pin. Only `id`, `session`, `kind` and `expected_version`
can be mapped; omitted configuration mappings resolve to `body`. Schema
`default` is documentation, not automatic mutation by a JSON Schema validator.
The pin requires all four mappings explicitly. Selector support, versioned-name
immutability, authentication, ambiguity handling, byte limits and exact restore
equality remain binding semantic checks, not JSON Schema guarantees.

`band_proposal_body` permits omission of the path-carried session on binding
adoption. `band_envelope` remains the complete normalized message. The named
`carrier_http_identity` and `band_carrier_http_identity` require a top-level
`carrier` pin; `band_carrier_identity` fixes Band's exact `band-room/1` map.
Existing `http_identity` and `band_http_identity` shapes keep the pin
optional so earlier fixtures do not claim adoption. The nested compiler
identity and pure reducer/checkpoint schemas are unchanged. See the
[carrier profile](../transport.md#carrier-map-profile) and
[Band map](../band-transport.md#band-carrier-map) for adoption obligations and
the distinction from currently implemented runtime endpoints.

After changing `spec/tools/buildv2schemas.py`, regenerate its artifact and the
inheriting coordination, participant and contribution bundles with their
corresponding `build_*_schemas.py` generators. The carrier additions do not
rewrite the earlier `protocol.schema.json` registry. Check generator/artifact
equality, all four Draft 2020-12 schemas and the actual configured/pinned map,
identity and body examples; retain the existing profile fixture checks.

The optional OpenAI binding adds prepared request, captured result, provider
identity, price policy, per-response usage and aggregate usage definitions. Its
portable fixtures include opaque API metadata and an independently stated cost
calculation. The normal gate decodes the recorded result without network access.

`service-config.schema.json` defines standalone room/agent configuration. It is
generated by `spec/tools/buildserviceschema.py`; the normal check verifies its
identity and validates the deployment examples. Runtime validation additionally
checks private-file ownership, absolute command/path safety, TLS URL semantics,
contract identities and actual engine/store startup. Optional fields are omitted,
not null. Credential values live in separate private files or provider environment.

JSON Schema is only the structural layer. Implementations must additionally check
UTF-8 byte limits, Unicode 16 grapheme counts, safe canonical encoding, checksums,
source identities, role/reference relationships, state invariants and transactional
ordering. JSON Schema `maxLength` does not replace a grapheme or byte bound.

Run `python -m contracts.spec.tools.buildschemas` only when intentionally changing the
schema source, then inspect the diff and run `spec/tools/checkspec.py`.
The checker compares both schema files and `requirements.json` with their
reviewed generator definitions, and requires the manifest revision to match
the catalog. A stale artifact fails validation; importing the generators or
running the checker never rewrites it. Change the generator first, regenerate
explicitly, then review the resulting artifact and its affected vectors.
