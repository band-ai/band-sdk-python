# Conformance bundle

## Current target and retained compatibility inventory

New implementations target engine `0.2.0-lab.1`, not `0.1.0-lab.1`. Read the
[current profile](../profile-v2.md), [current requirements](../requirements-v2.json),
[exact file source](../file-identity.md) and [coordination profiles](../coordination-profile.md).
Current compilation takes `band-contract/file-source/1`; a normalized card/body
pair cannot establish the required exact file identity.

The executable bundle is **current-only** after X4 wave2. Its
[retirement inventory](legacy-removal-v2.json) records the exact 62 retired
legacy-source cases. The unchanged [baseline pins](baseline-v1-pins.json) and
[assertion parity map](assertion-parity-v2.json) retain the 316 original
obligations: 229 unique approved current replacements, plus 87 assertions in
74 unchanged source-free cases (16 canonical/wire and 58 carrier cases).
Historical source and full expected outputs remain in the immutable prerequisite
commit and preserved original worktrees; they are not current execution inputs.

The default checker executes every current/source-free manifest case. A
current-only adapter can pass it without supporting removed authoring forms.
`--case-prefix` selects adapter execution only; full structure, pins and parity
still validate. The five original non-case artifacts remain immutable evidence:
the original 33 Band wire examples are schema-only historical evidence, while
the current 34 Band examples have the checked current source/binding case. The
historical file stays pinned in the manifest but is not listed as an example of
any requirement in [coverage.json](coverage.json).
The retained [schema registry](../schemas/protocol.schema.json) validates the
frozen wire/artifact shapes, not legacy compiler admission. Current compilation
uses the [current schema](../schemas/protocol-v2.schema.json) and descendants.

Current carrier cases already include file-source compilation. The
[v2 checks](../tools/checkv2.py) and [coordination checks](../tools/checkcoordination.py)
cover additional current behavior outside the manifest-pinned case inventory.
Those scripts invoke the reference adapter directly and do not expose the
default checker's `--adapter-config` switch. Passing them is local reference
evidence, not independent implementation qualification. A current-profile claim
needs the applicable requirements and semantic assertions, not merely a
hash-valid bundle.

For executable Band/HTTP/email normalization examples and their command-exit
receipt, see [runnable carrier examples](../carrier-examples.md). That local
example check is separate from the portable conformance gate below.

`manifest.json` pins each `case-*.json` by SHA-256. Each case has a profile, ID,
requirement IDs, ordered `requests`, the same number of complete `expected`
responses, and explicit semantic `assertions`. An assertion selects a response
index and an RFC 6901 JSON Pointer, then compares it with `equals`. The full
outputs come from the reference adapter; assertions are independently stated
expectations. This is not a claim of a complete second engine implementation.

Run `.venv/bin/python -m contracts.spec.tools.checkspec` from the repository root after
compiling `contract-lab` in the development environment. The gate checks schema
definitions, requirement references, links, fixture hashes, structural validity,
independent assertions and every adapter response. `--schema-only` omits adapter
execution and must not be described as an engine conformance pass.

Compiler error objects preserve the exact `code` and `line`; only their
diagnostic `detail` may vary between implementations. Its key must still be
present and its value must be protocol JSON. Success objects, all other errors,
state, decisions, metadata, ordering and hashes are compared in full. The
reference diagnostic remains in each fixture for inspection. Run the checker
regressions with `.venv/bin/python -m unittest discover -s spec/tools -v`.

## Coverage and limits of a pass

The generated [coverage index](coverage.json) lists every requirement of the
first catalog, [requirements.json](../requirements.json): its profile
applicability, linked cases/recorded artifacts, and the complete acceptance
obligation. Empty example lists are intentional and visible. It has no row for
the current profile's catalog, [requirements-v2.json](../requirements-v2.json).
That catalog has its own [v2 coverage index](coverage-v2.json), generated by
`spec/tools/buildcoverage.py` from the requirement tags in
`spec/tools/v2trace.py`. Every `checkv2.py` and `checkcoordination.py`
assertion carries those tags, and both checkers refuse to run an untagged
check. Every pinned `case-v2-*` vector in `manifest.json` is tagged the same way
and counted in the index as `manifest:<case id>`; its first-catalog IDs stay in
the manifest. The v2 index lists each row's acceptance obligations with the checks
tagged to them, names every obligation with no tagged check under
`unasserted`. A check with no v2 row carries an explicit marker instead of
requirement IDs: harness checks are listed under `tooling_only_checks`, and
checks of a specified rule that the catalog has no row for yet are listed
under `checks_without_v2_row`, grouped by the spec file that states the rule. The
index has `qualification:"not_assessed"`: an example link is not proof of every
clause of a requirement, and no requirement becomes accepted merely because it
has a link. Native loader, persistence, isolation and transport tests are
additional evidence; they are not silently counted as portable adapter cases.

The checker validates the full index against the requirement catalog and
manifest. It rejects unknown or conflicting requirement labels, duplicate case
identities, omitted fixture files, and stale coverage. Counts by profile overlap
when a requirement applies to several profiles; do not sum them as a global
requirement count.

| Check result | What it establishes | What remains separate |
|---|---|---|
| `--schema-only` passes | Artifact structure, generator agreement, hashes, assertions and index consistency | No engine, program replay or provider execution was tested |
| Default checker passes | The above plus all retained-and-added adapter outputs and recorded reference-host replay/provider fixtures | Complete current-profile coverage, requirement acceptance, independent engine proof, deployment, live model quality and load |
| `--adapter-config` passes | That adapter matches the executed portable cases; recorded host probes still use the reference Python runtime | Current-profile requirements outside those cases; the supplied adapter's persistence, host isolation and live-provider implementation |

The final report always names the number of requirements with and without
examples and says `qualification:"not_assessed"`. An implementation ledger must
assess each applicable acceptance obligation using its own evidence. See the
[completion contract](../implementation-guide.md#completion-contract).

To check another implementation, supply `--adapter-config path.json`, where the
file is a non-empty JSON array of non-empty strings: the executable and its
arguments. Any other value, including `[]`, `{}`, `null`, `0` or `""`, is refused
before a check runs; only an absent option selects the bundled reference adapter.
The report's `adapter` field records `kind` (`reference` or `configured`) and the
`argv` that ran. The driver uses no shell. The
adapter accepts UTF-8 JSON lines on stdin, emits exactly one JSON response per
request on stdout, and reserves stderr for diagnostics. Every case begins with
its own setup. Handles are local to the harness and may be reused by later cases.
The process must finish successfully after EOF. Each request is bounded to 2 MiB.

Response JSON may use insignificant whitespace and any valid JSON key order;
the driver compares canonical values. It rejects duplicate keys at every depth,
floating-point/exponent notation, nonfinite or unsafe numbers, unpaired
surrogates and non-UTF-8 output before comparison. Ordinary JSON decoding that
silently keeps the last duplicate key is insufficient for this boundary.

The reference driver also limits the whole input stream to 16 MiB, combined
stdout/stderr to 16 MiB, and the process lifetime to 30 seconds. Exceeding a
bound or exiting unsuccessfully fails the run. Handles are opaque test keys in
three separate namespaces: compiled contracts, sessions and room-event states.
A successful `compile`, `new`, `restore` or `room_new` replaces its named handle;
an error leaves that handle unchanged. `step`, `tick`, `room_step`, `host_signal`,
`stop_contribution` and `fail_contribution` retain their returned next state even
on rejection. A successful `view` retains its
advanced state; a failed projection leaves the harness handle unchanged.
`query`, `checkpoint`, `check`, `wire`, `wire_encode` and `canonical` do not mutate handles.
`wire_step` decodes the original frame with its carrier options before calling
the real session engine. A decoding error leaves the session handle unchanged;
an engine decision retains its returned next state, as with `step`.

Unknown operations, unknown required handles and malformed harness requests
return `{error:"adapter_input"}` in the reference adapter. These are harness
errors, not room admission decisions. Negative protocol inputs inside otherwise
valid requests return the operation's specified error or rejection. Responses
stay in request order; the adapter must not sort, omit or combine them.

| Operation | Required request data | Response |
|---|---|---|
| `compile` (current) | `handle`, `source: {profile:"band-contract/file-source/1", format, content, sha256}`; `format` is `frontmatter` or `standard`, and `standard` also requires `body` and `package_name` | `{ok: compiled}` or `{error: compiler_error}` |
| `query` | `contract`, `selector`, optional `name` | `{ok: selected_metadata}` or `{error: code}` |
| `new` | `contract`, `handle`, `config` | `{ok: checkpoint_data}` or `{error: code}` |
| `step` | `handle`, `actor`, `now`, `message` | `{decision, state: checkpoint_data}` |
| `host_signal` (declared host extensions) | `handle`, `now`, trusted `event` | `{decision: host_decision, state: checkpoint_data}` |
| `stop_contribution` (`room.contributions/1`) | `handle`, `actor`, `now`, `report`, fresh trusted `room_policy` | `{decision, state: checkpoint_data}` |
| `fail_contribution` (`room.contributions/1`, host only) | `handle`, `now`, trusted `report` | `{decision, state: checkpoint_data}` |
| `tick` | `handle`, `now` | `{decision: {status, optional reason}, state}` |
| `view` | `handle`, `actor`, `now` | `{ok: projection}` or `{error: code}` |
| `checkpoint` | `handle` | `{ok: room_checkpoint}` or `{error: code}` |
| `restore` | `contract`, `handle`, `checkpoint`, `now` | `{ok: checkpoint_data}` or `{error: code}` |
| `check` | `contract`, `projection`, `actor`, `now`, `message` | Local admission decision |
| `room_new` | `contract`, `handle`, room `config` | `{ok: room_state}` or `{error: code}` |
| `room_step` | `handle`, `actor`, `now`, sessionless `message` | `{decision, state: room_state}` |
| `wire` | `bytes` as a JSON string, optional `carrier`, `transport`, `max_bytes` | `{ok: envelope}` or `{error: code}` |
| `wire_encode` | `message`, same optional Wire options | `{ok: encoded_JSON_string}` or `{error: code}` |
| `wire_step` | `handle`, `actor`, `now`, `bytes`, same optional Wire options | `{decision, state: checkpoint_data}` or decoder `{error: code}` |
| `canonical` | `value` | `{bytes: base64, sha256}` |

State/checkpoint field names and values are defined in the protocol schemas.
Select the [current schema bundle](../schemas/protocol-v2.schema.json) for base
file-source cases and its [coordination](../schemas/protocol-coordination.schema.json),
[participant](../schemas/protocol-participants.schema.json) or
[contribution](../schemas/protocol-contributions.schema.json) descendants when
those features are declared.
`new.config` contains host-derived policy, capabilities and bindings. Current
`step`, `view`, `wire_step` and member contribution controls use fresh trusted
`room_policy` separately from message payloads. This is a trusted harness pipe,
not a public agent API: its actor, clock, host events and host-failure reports
cannot be taken from unauthenticated request data. Explicit unchecked mode is a
local test option at session creation, never hosted qualification.
`query` selectors are `contract`, `role`, `type`, `state`, `outcome`, `room` and
`any_state`. Source discovery and filesystem safety also require the documented
loader tests; normalized compile cases do not certify those boundaries.

The mixed-profile bundle runs compiler, session-engine and room-event operations in
one stream. An implementation of a subset must supply the prerequisite adapter
operations or maintain an explicitly selected case list in its evidence; it
must not label a partial run as the default full-bundle pass. A harness compiler
used to feed a reducer must be identified separately from the reducer under test.

`invocation-replay.json` supplies exact worker input, raw output bytes, private
journal hashes and nonexecuting replay expectations. Its complete and interrupted
histories must respectively reuse the recorded result and hold. Private journal
canonicalization is intentionally distinguished from the public protocol's
uppercase control escapes; see the remote-runtime specification.

The independently published [Unicode corpus](../../header-spikes/priv/unicode16/README.md)
defines all 1,093 official extended grapheme boundary cases. Its source hashes
and license are included. Generated implementations must pass it as well.

## Band examples

`band-wire-examples.json` contains 33 independently specified structural
expectations, including malformed actor UUIDs, caller authority fields,
configuration bounds and missing inbox capability. A hash-valid fixture still
fails if a positive/negative expectation disagrees with its named schema.
The `valid` flag means schema validity only; it is not a claim that a room,
principal or session exists or that the authority would accept the request.

`case-v2-band-session.json` executes 20 compiler/reducer requests using canonical
Band session and typed actor IDs. Its source and configuration must match the
`create` example in `band-wire-examples-v2.json`. Both roles bind agents, and
every session call carries a trusted room policy. It checks role rules,
references, views, terminal reconciliation, conflicting retry actors/versions,
a deadline that fires at exactly its due time, and refusal of an unbound
principal. These are engine examples, not simulated HTTP authorization or
database acceptance.
The report separately counts `band_wire_examples`, sets
`band_live_checked:false`, and retains `qualification:"not_assessed"`.
The [integration acceptance matrix](../band-integration.md#recover-and-qualify-the-boundary)
identifies the additional native/runtime checks.

## Intentional updates

### Inbox paging vectors

[`inbox-vectors.json`](inbox-vectors.json) is a separate, independently authored
`band-contract/inbox-vectors/1` corpus for `contract-room/inbox/1`. It is not a
pure-engine `case-*.json` and is checked by its own gate, not by `checkspec.py`
or `checkv2.py`. No shared wire schema or existing fixture pin changes.

```sh
python -m contracts.spec.tools.checkinbox
python -W error -m unittest discover -s spec/tools -p test_inbox_vectors.py -v
```

Cases provide a trusted authority `head`, ordered `records` with opaque
`position` values, authenticated `actor`/`session`, an inbox `request`, and an
independent `expected` response. A record's `receipt` names a retained original
accepted decision, or is null for a nonacceptance/internal position. Templates
start with empty `decision.payload.text`; replace it with `text_fill.scalar`
repeated `text_fill.count` times. `canonical_bytes` independently pins the
expanded decision's canonical protocol JSON UTF-8 length. This recipe keeps
exact-2-MiB and oversized cases portable without checking megabytes into Git.
Successful expected `events` list template names in order; expand them to the
unchanged complete decisions before comparison. Failed pages specify only their
HTTP `status`, because transport error bodies are binding-specific and MUST NOT
acknowledge a cursor or events. The one exception is the shared ahead-of-head
code: a 409 vector is `{status:409,body:{code:"cursor_ahead"}}`, and the checker
requires an adapter's 409 body to be `{error, code:"cursor_ahead"}`, with
`error` a string.

The corpus covers exclusive/gapped positions, hidden scan-limit accounting,
empty advancing pages, future-cursor conflict (409), malformed/unsafe input
refusal (400), safe-integer input bounds,
exact-byte equality, UTF-8 versus code-point lengths, later overflow with a
hidden prefix, first-visible overflow, and resuming at the blocked receipt.
`storage` labels `restart`, `compacted` and `archived` tell an adapter which
retention scenario to exercise. `replay_of` pins a retention case to its live
baseline's original positions, head, decisions and expected response. These
labels themselves do not implement or prove actual persistence.

For another implementation, use `--adapter-config path.json`, a JSON array of
trusted command arguments. Its JSON-lines requests carry each case **without**
`expected`, plus the referenced compact receipt templates and byte bound.
The adapter seeds its own trusted state, performs the declared storage scenario,
and emits exactly one `{status:200,body:{cursor,events}}` response per success,
or `{status:400|503}` (optionally a binding error body) or
`{status:409,body:{error,code:"cursor_ahead"}}` per failed page. The driver
uses no shell and bounds execution time and input/output. This harness is not a
public HTTP authority API and MUST NOT accept participant-supplied retained
receipts or heads. Actual authorization, durable writes, restart/compaction/
archive execution, response framing and joint capacities remain qualification
obligations of the adapter/deployment under test.

Without an adapter, the checker validates the receipt/request/response schemas,
byte pins and independent expectations against an executable specification
oracle only. Reports distinguish `vector_oracle_checked`, `adapter_checked`,
and `band_live_checked:false`, and always retain `qualification:"not_assessed"`.

D-9 cases (`carrier-*`) use current profile-2 source bytes and independently
specified HTTP/email, omission, conflict, trust, type and retry assertions.
`carrier-cross-carrier-retry` decodes both carriers before real engine admission;
it is not a pair of hard-coded normalized `step` requests. Actor and clock are
still supplied by the harness's trusted context, never by carrier fields.
Non-body values in `carrier.fields` declare the external tokens; `transport` keys are those tokens.
There is no separate `sources` option.
An absent `carrier` option preserves the legacy field-keyed id/session API.

To add or explicitly regenerate only this workstream's fixtures:

```sh
python -m contracts.spec.tools.generatevectors --case-prefix carrier- --write
python -m contracts.spec.tools.checkspec --case-prefix carrier-
```

Selected generation retains unrelated case bytes, artifact bytes and their pins,
then updates the manifest and coverage index. Failed independent assertions do
not write selected fixtures. The checker always validates the full bundle's
structure and hashes, but selected adapter execution is reported explicitly in
`adapter_scope`, `adapter_cases`, and `adapter_requests`. A selected run is not
a full adapter conformance pass. Cases use their applicable current or source-free wire schema.

Review semantic changes before changing fixtures. The current-only generator
must never re-evaluate the retired corpus or recreate a retired case. `--write`
regenerates current vectors and coverage while retaining surviving source-free
pins; the parity gate also verifies the exact retirement list.

```sh
python -m contracts.spec.tools.generatevectors --write
.venv/bin/python -m contracts.spec.tools.checkspec
```

Catalog and schema regeneration is separate intentional maintenance, not a
reason to refresh frozen evidence. Remove compatibility cases only after their
current replacements and independent semantic assertions are gated.

Inspect changed assertions and full expected values independently. Keep observed
RED/GREEN evidence for behavior fixes; never weaken a fixture to make a regression
pass. For dependency updates, `spec/tools/lockpython.py` locks exactly the Linux
x86_64 / CPython 3.12 closure of the exact pins in `requirements-dev.in`: it refuses a
missing, out-of-range or stray wheel in `.cache/requirements` before any network call,
verifies each wheel hash against official PyPI version metadata and writes exact locks
plus `dependency-manifest.json`. An update is explicit maintenance, not a build step.

Persistence, transport, sandbox, live-provider quality and load qualification are
separate requirements. Reducer conformance alone does not certify those profiles.

## Deliberately invalid source requests

Fail-closed vectors may include malformed source envelopes. A case records each
intentional schema violation in `source_schema_assertions` as a unique request
index and expected boolean validity. Undeclared requests must remain valid.
The checker independently verifies that schema oracle and still runs the input
through the selected adapter and compares its precise rejection. This does not
permit skipping adapter checks or relabeling a malformed positive example.

Typed-roster vectors declare `schema_profile: 4` explicitly. Other current
vectors default to schema profile 2; source-free wire vectors retain schema
profile 1. The checker verifies every current registry against its independent
builder before using an explicitly selected profile. It never chooses a state
profile from checkpoint field shape.
